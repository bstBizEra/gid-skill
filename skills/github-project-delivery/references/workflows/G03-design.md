# G03 — Design

**Trigger:** Define a product change, feature, user journey, API contract, or architecture decision.
**Inputs:** Problem, affected users, constraints, existing product behavior, research sources, acceptance owner.
**Capability assumptions:** Research and repository context are used only when available; missing evidence stays explicit.
**Actions:** State the outcome; research relevant evidence; map journeys and contracts; define acceptance examples and risks; record unresolved decisions.
**Output:** PRD or specification, architecture/UX decisions as needed, and testable acceptance matrix.
**Exit and recovery:** Keep unknowns explicit. If a decision needs an owner, provide bounded options and pause dependent implementation.
**Authority limit:** A design proposal is not approval to implement, publish, or change policy.
